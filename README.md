# RepoGit

Настольная библиотека публичных GitHub-репозиториев. Разработчик — PATRIOTIK.

## Запуск и сборка

Необходимы Node.js 20+ и npm. Установите зависимости командой `npm ci`, затем запустите приложение через `npm start`. Сборка Windows (установщик и переносимый EXE): `npm run build:win`. Сборка RPM: `npm run build:linux`; для этого необходимы инструменты RPM.

## GitHub

Вход осуществляется с личным токеном доступа. Для создания собственных репозиториев и загрузки релизов требуется соответствующее право GitHub. Токен хранится в защищённом хранилище операционной системы, если оно доступно; иначе — только в памяти. Проверьте выбранные файлы на наличие секретов до публикации. Приложение создаёт новый репозиторий, не перезаписывая существующий. При неудачной загрузке релиза на GitHub может остаться черновик.

Проверка обновлений использует публичный репозиторий `RUZIK558/RepoGit`. Обновление скачивается отдельно; скачанный установщик или portable-версию нужно запустить вручную. Наличие файла в GitHub не гарантирует его безопасность.

## Автоматическая публикация следующих версий

В исходниках есть GitHub Actions workflow `.github/workflows/release.yml`. После размещения исходников в своём репозитории и разрешения GitHub Actions обновите `version` в `package.json` и `package-lock.json`, затем создайте и отправьте совпадающий тег вида `v0.4.0`. Workflow соберёт установщик, portable EXE и RPM и создаст GitHub Release со всеми файлами. Для работы требуется разрешение Actions на запись в содержимое репозитория; сборки не подписываются. Первый релиз и репозиторий сами по себе этим архивом не создаются.

Если публикуете эту папку через RepoGit с classic token, для файла `.github/workflows/release.yml` GitHub дополнительно требует scope `workflow` (помимо `repo`). Удалите этот файл из выбранной папки, если не хотите давать токену право менять workflows.

## Возможности версии 0.6

Избранные репозитории, поиск по загруженным файлам, открытие расположения файла, проверка последнего стабильного релиза, сравнение SHA-256 с контрольной суммой GitHub при её наличии. Отмена активной загрузки и быстрый переход из библиотеки к файлам релиза. При запуске RepoGit в фоне проверяется наличие его новых версий; скачивание и установка остаются ручными. Контрольная сумма GitHub не подтверждает безопасность программы или личность автора.

## Версия 0.7: macOS, фильтры и Proton

- macOS: поддерживаются DMG и ZIP с macOS в имени. Выбор архитектуры по имени — приблизительный; проверяйте файл у автора. DMG/ZIP открывается средствами macOS, дальнейшая установка выполняется пользователем. Сборка ZIP x64 и arm64: `npm run build:mac`. Эти сборки не подписаны и не нотариально заверены Apple, поэтому macOS может их блокировать.
- Описание README показывается как текст; внешние скрипты и HTML не выполняются.
- Фильтры по ОС проверяют имена файлов последнего стабильного релиза. Они могут пропустить подходящий файл и расходуют лимит GitHub API.
- В Linux Windows EXE можно запускать с установленным Steam Proton 9.0-4. Если Proton в нестандартной библиотеке, укажите файл `proton` в папке `Proton 9.0-4`. Для каждого репозитория создаётся отдельный совместимый префикс; работоспособность сторонних программ не гарантируется.
- Новые версии RepoGit проверяются при запуске, но скачивание и установка остаются ручными. Для настоящего автообновления потребуются отдельные механизмы распространения и испытания для каждой ОС; RPM может требовать прав администратора, а macOS — подписанную и нотариально заверенную сборку.


### Обзор и поиск
Каталог и поиск прокручиваются непрерывно: RepoGit подгружает новые результаты по мере приближения к концу списка. Фильтр ОС проверяет файлы последнего стабильного релиза и может не найти файлы с нестандартными именами. Массовая проверка расходует лимит GitHub API; при ограничении запросов повторите загрузку позднее.


### Версия 0.9: лимиты и вход
Войдите на вкладке GitHub с личным токеном (не с паролем). Авторизованные запросы используют ваш токен только для GitHub API; при фильтрации имена файлов до 18 репозиториев запрашиваются одним GraphQL-запросом и кэшируются на 10 минут. Без входа проверка по-прежнему использует отдельный REST-запрос на репозиторий. GitHub устанавливает лимиты даже для авторизованных запросов. Фильтр проверяет первые 100 файлов последнего стабильного релиза и может пропустить нужный файл.


### Обновление приложений и установщики Windows

В библиотеке нажмите «Проверить релиз» и выберите файл последнего стабильного релиза. Новая загрузка добавляется отдельной записью; предыдущая не удаляется. Для Portable запускайте новую запись. Для установщика нажмите «Запустить установщик» и завершите обновление вручную. После установки используйте «Указать установленную программу», выбрав её EXE, — кнопка запуска будет открывать программу, а не скачанный установщик. RepoGit распознаёт установщики по имени; файлы с нестандартными именами проверяйте самостоятельно. Удаление загрузки не удаляет установленную программу. Проверяйте источник и совместимость файлов.

### Звёзды GitHub

На странице репозитория авторизованный пользователь может поставить или убрать звезду GitHub. Состояние загружается из GitHub; избранное RepoGit хранится отдельно. Для fine-grained personal access token нужны права пользователя **Starring: Read and write**. При ошибке доступа проверьте разрешения токена.
